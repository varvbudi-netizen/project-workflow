# Проектная работа и порядок проекта

## Что пользователь имеет в виду

Это переносимый комплект для организации проектной работы. Он помогает создать структуру проекта, вести документацию, проверять изменения и передавать работу между участниками и агентами.

Корень комплекта — каталог, в котором находится этот `SKILL.md`. Все ссылки ниже разрешай относительно него. Для запуска создателя используй абсолютный путь к `scripts/create_project.py` в этом каталоге: текущим рабочим каталогом агента может быть другой проект.

## Источники — читать по задаче

- Всегда начни с [README комплекта](README.md): состав, создание, проверки и границы применения.
- Для применения прочитай [копируемый AGENTS.md](template/AGENTS.md). Это образец для будущего проекта; его незаполненные сведения не описывают существующий проект пользователя.
- Для сортировки документов: [навигатор](template/docs/README.md), [правила задач](template/docs/tasks/README.md), [карточка](template/docs/tasks/TEMPLATE.md), [архив](template/docs/archive/README.md).
- Для причин устройства: [структура проектной работы](PROJECT-STRUCTURE.md) и [рабочий цикл](WORKFLOW.md).
- Для исследования создания решения: [AI-SOLUTION-RESEARCH.md](AI-SOLUTION-RESEARCH.md). Описанная эффективность процесса ещё не подтверждена сравнительными испытаниями; не представляй её доказанной.

Если связанные файлы недоступны, проверь, что установлен весь каталог комплекта. Не восстанавливай его содержимое по предположениям.

## Выбери действие по запросу

**Найти или объяснить.** Покажи точный путь и нужные файлы, объясни относящиеся к вопросу правила. Сам запрос на поиск не означает перенос файлов или перестройку текущего проекта.

**Создать новый проект.** Используй существующий создатель из комплекта. Требуется Python 3.11 или новее, сторонние библиотеки не нужны. Укажи фактические название, назначение и новый, ещё не существующий каталог:

```powershell
python "<каталог-комплекта>/scripts/create_project.py" "<новый-каталог-проекта>" --name "Название проекта" --purpose "Для кого и какую задачу решает продукт"
```

Создатель отказывается менять существующий каталог. Не обходи эту защиту. Затем прочитай созданный `AGENTS.md`, заведи первую карточку задачи и зарегистрируй её в `docs/STATUS.md`. Заполни паспорт, реальную карту частей и источников правил, команды и ограничения. При отсутствии кода или рабочей среды прямо укажи это; не выдумывай реализации и проверки. Каталоги исходников, технологии и службы добавляй по потребностям продукта.

**Привести существующий проект к порядку.** Сначала прочитай действующие инструкции и навигацию, проверь состояние файлов и активную работу. Сопоставь имеющиеся документы с ролями шаблона. Адаптируй недостающие части, сохраняя подтверждённые сведения и полезные ограничения; не перезаписывай существующие `AGENTS.md`, документы, исключения Git или автоматические проверки целиком образцами. Перемещай историю с обновлением ссылок и сохранением истории Git там, где он используется. Не удаляй материалы только из-за возраста. При чтении кода соблюдай действующую маршрутизацию инструментов проекта. Перенос документов сам по себе не требует реорганизации кода или выпуска приложения.

**Продолжить работу в таком проекте.** Читай `AGENTS.md`, `README.md`, `docs/STATUS.md` и существующую карточку нужной задачи. Сверь сохранённое состояние с фактами и продолжай ту же карточку. Остановка сеанса не завершает задачу.

**Изменить сам комплект.** Прочитай `AGENTS.md`. Копируемый источник — `template/`. Изменение комплекта не обновляет ранее созданные проекты автоматически; другие проекты не изменяются ради сопровождения шаблона.

## Обязательное устройство документов

| Место | Назначение |
|---|---|
| `README.md` | Назначение продукта и точка входа |
| `AGENTS.md` | Короткая карта реального проекта, источники правил, проверки и порядок агента |
| `docs/README.md` | Реестр действующих документов со ссылками |
| `docs/PROJECT.md` | Потребность, пользователи, сценарии, границы и критерии |
| `docs/STATUS.md` | Подтверждённое состояние, активные задачи, рабочая версия и ограничения |
| `docs/ARCHITECTURE.md` | Части системы, ответственность, источники правил и зависимые потребители |
| `docs/DEVELOPMENT.md` | Проверенные команды запуска и проверок с рабочим каталогом |
| `docs/OPERATIONS.md` | Рабочие среды, выпуск и восстановление; до появления среды это обозначается прямо |
| `docs/tasks/` | Текущая работа: одна продолжаемая карточка на цель |
| `docs/archive/` | Исторические материалы; завершённые карточки — в `docs/archive/tasks/` |

Карточка называется `YYYY-MM-DD-короткое-название.md`. В ней вместе хранятся цель и критерии, область работы, исходные факты и неизвестные, решение, существенные действия, фактические проверки, ограничения и передача следующему сеансу. Не размножай один материал в плане, журнале и отчёте. Для маленькой задачи достаточно короткой карточки.

Устойчивое правило живёт в одном профильном документе; навигаторы ссылаются на него. Текущие справочники имеют статус и дату. Архив описывает историю, не нынешнее поведение. Временные файлы, сборки, журналы и индексы отделяются от исходников и исключаются из Git по назначению. Секреты не попадают в документы, вики и историю.

## Рабочий цикл и проверяемое завершение

Потребность → наблюдаемые критерии → факты и неизвестные → выбор подхода → проверка существенного предположения → ограниченное изменение → проверка результата → передача работы.

Для нетривиального выбора комплект предусматривает сравнение четырёх жизнеспособных вариантов; если реальных вариантов меньше, объясни это, не выдумывай варианты ради числа. Простая правка не требует такого исследования.

В проекте с подключённой проверкой выполни из его корня:

```powershell
python scripts/check_project.py
python scripts/check_project.py --ready
```

Первая команда проверяет структуру, локальные ссылки и поля образца. Вторая дополнительно обнаруживает незаполненные начальные сведения. У нового проекта до предметного заполнения отказ второй ожидаем и должен быть назван прямо. Эти команды не доказывают работоспособность продукта. При адаптации существующего проекта проверь совместимость проверки с фактической структурой, не меняй требования продукта ради её прохождения.

Проверки поведения выбирай по изменению: пользовательский путь — реальным сценарием; сохранение — записью, повторным открытием и чтением. Создание запроса на слияние, слияние и установка версии — отдельные события; подтверждай выполненное отдельно и в пределах разрешённой задачи.

Перед окончанием сеанса сохрани в карточке сделанное, доказательства, ограничения и следующий конкретный шаг. При завершении задачи перенеси карточку в архив, обнови ссылки, активный реестр и затронутые справочники. Устойчивые выводы сохраняй в принятой проектом памяти со ссылками на источники, если такая память подключена.

Для изменения самого комплекта проверки из его корня указаны в README: `python template/scripts/check_project.py --template` и `python -m unittest discover -s tests -v`. Не запускай их ради простого поиска или объяснения шаблона.
