# Задачи и передача работы

Одна карточка хранит цель, существенные решения и журнал одной задачи. Не создавайте параллельно план, отдельный журнал и отчёт с одинаковым содержимым.

## Начало

1. Прочитайте реестр в [состоянии проекта](../STATUS.md). Проверьте, не выполняет ли кто-то уже ту же работу.
2. Скопируйте [образец](TEMPLATE.md) в файл вида `YYYY-MM-DD-короткое-название.md` в этом каталоге.
3. Запишите исполнителя или идентификатор сессии, цель, область файлов и критерии результата.
4. Добавьте относительную ссылку на карточку в реестр активных задач. Это делает работу видимой другим агентам.

Карточка небольшой задачи может быть короткой. Длинная работа ведётся в той же карточке, пока сохраняется одна цель.

## Во время работы и при смене агента

После существенного решения, проверки или смены направления обновите карточку. Перед завершением сессии обязательно запишите фактическое состояние, незавершённый шаг и способ его продолжения. Новый агент сначала читает эту запись и сверяет её с текущими файлами.

Статусы: `подготовка`, `в работе`, `проверка`, `ожидает данных`, `завершена`, `отменена`. Для ожидания указываются конкретное препятствие и действие, которое его устранит. Остановка сессии сама по себе не означает завершения задачи.

При одновременной работе задайте владельца каждой области. Совпадающие файлы, общая база и публикация требуют координации; список задач не является технической блокировкой.

## Завершение

- Сверьте результат с критериями и запишите доказательства.
- Перенесите устойчивые сведения в нужный справочник.
- Переместите карточку в `docs/archive/tasks/`, сохранив историю Git, если проект использует Git.
- Удалите запись из активных задач, обновите действующие ссылки и кратко зафиксируйте существенный результат в состоянии проекта.
- Выполните проверку структуры документов.
