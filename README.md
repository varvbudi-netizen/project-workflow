# Шаблон начала проекта и работы агентов

Статус: рабочий комплект. Публичная переносимая версия: 2026-10-30.

Комплект задаёт общий порядок проектной работы: понятный вход для агента, источники правил, карточку задачи, осмысленные проверки, историю решений и проверяемую структуру документов. AGENTS.md связывает назначение продукта, карту репозитория, ответственные модули, защищаемые условия, проверки и выпуск.

## Скачать комплект

```powershell
git clone https://github.com/varvbudi-netizen/project-workflow.git
cd project-workflow
```

Все команды ниже выполняются из корня скачанного комплекта, если явно не указан созданный проект.

## Установить навык для агента

Корень репозитория — готовый каталог навыка: [SKILL.md](SKILL.md) использует соседние документы, `scripts/` и `template/`. Переносите каталог целиком; одного файла `SKILL.md` недостаточно.

Для Кодекса можно сразу скачать комплект в каталог пользовательских навыков:

```powershell
git clone https://github.com/varvbudi-netizen/project-workflow.git "$HOME/.agents/skills/project-workflow"
```

Если этот каталог уже существует, не заменяйте его вслепую: сначала сравните содержимое и сохраните собственные изменения. Для обновления чистой установленной копии используйте `git -C "$HOME/.agents/skills/project-workflow" pull --ff-only`.

После установки попросите агента: «Используй навык project-workflow: создай проект по нашему шаблону» или «Приведи документацию проекта к порядку по project-workflow». Если навык не появился в списке, перезапустите приложение. Формат и каталоги установки описаны в [официальной документации Кодекса](https://developers.openai.com/codex/skills).

В другом агенте с поддержкой формата Agent Skills — каталога инструкций и ресурсов для повторяемых задач — установите весь комплект в его каталог навыков. Если автоматического обнаружения нет, явно укажите агенту файл `SKILL.md` из скачанного комплекта.

## Начать новый проект

Нужен Python 3.11 или новее. Дополнительные библиотеки не требуются.

```powershell
python scripts/create_project.py ../my-project --name "Название проекта" --purpose "Для кого и какую задачу решает продукт"
```

Укажите **новый, ещё не существующий каталог**. Создатель проверит образец, скопирует файлы и подставит название, назначение и дату. Существующий каталог он не изменяет. Создание не публикует проект, не создаёт чат и не меняет настройки агента на компьютере.

Затем откройте созданный каталог своим агентом и отправьте:

> Начни работу по AGENTS.md. Прочитай состояние проекта. Оформи первую задачу в docs/tasks/, уточни только существенные неизвестные и заполни паспорт продукта. Преврати AGENTS.md в карту этого проекта: реальные части, точки входа, ответственные модули, источники правил и нужные проверки. Заполни связанные справочники. Если кода пока нет, обозначь это прямо и обновляй карту при его появлении. Выполни проверку структуры и готовности. Дальше работай по карточке задачи и сохраняй следующий шаг перед завершением сессии.

Агенту, который не подхватывает `AGENTS.md` автоматически, нужно один раз явно указать этот файл как вход. Установка комплекта сама по себе не подключает его ко всем будущим проектам: новый проект следует создавать этой командой или копировать содержимое `template/` с заменой полей.

## Что получает проект

```text
README.md                    Назначение и вход в проект
AGENTS.md                    Паспорт, карта проекта и порядок работы агента
.gitignore                   Исключения для временных данных и секретов
.github/workflows/hygiene.yml Автоматическая проверка структуры
docs/
  README.md                  Реестр действующих документов
  PROJECT.md                 Потребность, границы и критерии продукта
  STATUS.md                  Текущее состояние и активные задачи
  ARCHITECTURE.md             Границы, владельцы логики и карта модулей
  DEVELOPMENT.md             Проверенные команды запуска и проверок
  OPERATIONS.md              Выпуск, рабочая среда и восстановление
  tasks/
    README.md                Правила ведения задач
    TEMPLATE.md              Карточка: задача, решение, работа, передача
  archive/README.md          Правила хранения истории
scripts/check_project.py     Проверка структуры, ссылок и незаполненных полей
```

Каталоги исходников, зависимости, база, развёртывание и профильные навыки добавляются по потребностям продукта. Команды и адреса других проектов не переносятся автоматически.

## Две разные проверки

В созданном проекте:

```powershell
python scripts/check_project.py
python scripts/check_project.py --ready
```

Первая проверяет структуру, локальные ссылки и отсутствие незаменённых полей образца. Вторая дополнительно требует заполнить помеченные начальные сведения. Только что созданный проект проходит первую проверку и ожидаемо не проходит вторую: предметные решения ещё предстоит принять.

Обе команды проверяют документы. Проверки работоспособности продукта агент добавляет в `docs/DEVELOPMENT.md` и, когда это нужно, в автоматический процесс. Успешная проверка документов не подтверждает правильность приложения или выпуска.

В GitHub запускается первая проверка на запросах на слияние и изменениях основной ветки. После определения технологий добавьте соответствующие проверки продукта. Обязательность успешных проверок перед слиянием настраивается в защите ветки отдельно, если это поддерживается репозиторием.

## Как устроена работа

1. Агент читает правила, состояние проекта и свою карточку задачи.
2. Определяет потребность, критерии результата, факты и неизвестные.
3. Выбирает подход и при необходимости проверяет самое рискованное предположение.
4. Делает ограниченное изменение и проверяет фактическое поведение.
5. Обновляет затронутые справочники, фиксирует результат и следующий шаг.

Одна карточка совмещает план, существенные решения и журнал работы. Это уменьшает количество мест, которые нужно синхронизировать. Реестр активных задач показывает владельца и область правок, но не служит автоматической блокировкой файлов.

Проверки самого комплекта:

```powershell
python template/scripts/check_project.py --template
python -m unittest discover -s tests -v
```

Тесты создают отдельные временные проекты и проверяют их реальный запуск, защиту существующих каталогов и обнаружение нарушений. Доработки следует делать в `template/`, чтобы новые проекты получали один и тот же исходный порядок. Обновление комплекта не меняет ранее созданные проекты автоматически.

## Сопровождение

Комплект устанавливается целиком и не зависит от частной инфраструктуры. Изменения шаблона вносятся в `template/`; проверки выполняются на Python 3.11–3.13.
